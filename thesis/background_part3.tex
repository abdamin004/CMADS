\subsection{Memory and State in Multi-Agent Clinical Systems}
\label{subsec:memory_state}
% ─────────────────────────────────────────────────────────────────────────────

The systems reviewed so far treat each clinical case as a fresh problem.
Useful information from one case is not carried into the next: there is no
record of which evidence patterns supported which conclusions, no record of
which agents tended to disagree on which kinds of cases, and no record of how
the system handled similar patients before. This is a known limitation of the
foundational and coordination work and shapes the memory subsystem that the
thesis builds in Chapter~\ref{chap:methodology}.

The conceptual taxonomy used for the memory design in this thesis is drawn
from the Cognitive Architecture for Language Agents (CoALA) family of work.
CoALA distinguishes four memory categories. \emph{Working} memory holds the
state of the current task --- the prompt, the intermediate outputs, the
scratchpad. \emph{Episodic} memory is an append-only timeline of events from
prior runs, useful for replaying what happened in a particular case.
\emph{Semantic} memory stores summarised, condition-level aggregates --- for
example, the typical evidence patterns that supported a confirmed match for a
given disease across many runs. \emph{Case-based} memory stores prior
patients as searchable records that can be retrieved by similarity to the
current patient. The thesis instantiates all four tiers in
Section~\ref{sec:shared_memory}.

Three papers from the broader review intersect this design. RareAgents
combines persistent memory with tool use and shows that an open-source
backbone with memory beats a larger general model on rare-disease
diagnosis~\cite{Chen2024RareAgents}; this is the closest published example of
case-based retrieval changing diagnostic behaviour. MDTeamGPT introduces a
self-evolving memory that updates which discussion patterns work for which
case types~\cite{Chen2025MDTeamGPT}; the mechanism is closer in spirit to
semantic memory than to case-based memory. The MALADE pharmacovigilance
pipeline is the most direct example of retrieval-augmented generation in a
multi-agent clinical setting, and reports a 64\% reduction in hallucinated
drug--event associations when retrieval is added~\cite{Choi2024MALADE}; this
result motivates the NICE-guideline retrieval used by the Treatment Planning
agent in this thesis.

Most of these systems do not report how they prevent the case store from
retrieving near-duplicate prior runs of the same cases used for evaluation.
That risk can inflate apparent accuracy without genuine algorithm improvement.
The memory comparison in Chapter~\ref{chap:results} is therefore reported
cautiously across all available runs for each memory setting, with the
cohort-leakage risk stated explicitly instead of being hidden behind a single
headline accuracy number.

\subsection{Domain-Specific Clinical Workflow Deployment}
\label{subsec:domain}
% ─────────────────────────────────────────────────────────────────────────────

The previous sections focused on general design ideas. The papers in this group
look at systems built for specific clinical domains, including cardiology,
inpatient pathways, pharmacovigilance, emergency triage, and rare-disease
diagnosis. They are useful because they show how multi-agent ideas behave when
applied to real or realistic clinical tasks. Table~\ref{tab:tracker_domain} gives
an overview.

ZODIAC by Zhou et al. applies multi-agent design to cardiology
\cite{Zhou2024ZODIAC}. It uses five agents for cardiac data extraction,
arrhythmia detection, report generation, clinical reasoning, and human review.
The agents were fine-tuned on real patient data reviewed by cardiologists. The
system reached cardiologist-level performance on 7 of 8 metrics and outperformed
general-purpose GPT-4 on cardiac tasks. It is also relevant because it includes
human cardiologist review as part of the workflow.

MAP by Chen et al. studies inpatient pathway automation \cite{Chen2025MAP}. It
covers admission assessment, daily monitoring, medication planning, procedure
recommendation, and discharge summary generation. The authors also introduced
MAP-Bench, built from real EHR data across four departments. Splitting the work
by pathway stage improved workflow adherence by 23\% over single-agent baselines.
Department-specific agents also performed better than general agents.

ClinicalLab by Yan et al. is the broadest deployment in this review
\cite{Yan2024ClinicalLab}. It covers 11 departments and 1{,}500 real patient
cases. The system uses department-specific specialist agents, a Coordinator for
routing, and a Chief Physician for final synthesis. It achieved diagnostic
accuracy within 5\% of senior physicians and received a clinician satisfaction
score of 4.1/5. The Coordinator and Chief Physician roles are especially relevant
to this thesis because they resemble the orchestrator and reviewer roles.

MALADE by Choi et al. applies a RAG-based multi-agent pipeline to
pharmacovigilance \cite{Choi2024MALADE}. The system improved adverse drug event
identification precision by 18\% and recall by 12\% compared with single-agent
GPT-4. RAG reduced hallucinated drug-event associations by 64\%. The important
design point is that the orchestrator can reroute the task when retrieval quality
is weak, instead of passing poor evidence to later stages.

CDR-Agent by Xiang et al. automates clinical decision rules such as the HEART
Score, Wells Criteria, and Ottawa Rules \cite{Xiang2025CDRAgent}. Its
Select--Extract--Calculate--Recommend pipeline reached 94.2\% rule selection
accuracy and 89.1\% variable extraction F1 on 500 de-identified UCSF notes. UCSF
clinicians rated 91\% of recommendations as clinically acceptable or better. The
system also correctly declined to apply a rule in 88\% of out-of-scope cases,
which is useful evidence for deferral as a safety behaviour.

TriageAgent by Lu et al. focuses on emergency triage \cite{Lu2024TriageAgent}.
It uses a five-stage pipeline with confidence scoring and early stopping. If
agent confidence is high enough, the system stops further deliberation. It also
uses RAG over the Emergency Severity Index handbook. On GPT-3.5-turbo, it
outperformed MedAgents by 5.55\%. This supports confidence-aware stopping in
agent workflows.

RareAgents by Chen et al. addresses rare-disease diagnosis
\cite{Chen2024RareAgents}. It uses Llama-3.1-70B with persistent memory, medical
tool use, and five specialist MDT agents. On RareBench and MIMIC-IV-Ext-Rare,
RareAgents outperformed GPT-4o and domain-specific fine-tuned models. Tool use
also reduced hallucinated medication recommendations by 41\%. This is important
because it shows again that workflow, memory, and tools can matter more than
model size alone.

\subsection{Safety, Robustness, and Evaluation of Clinical MAS}
\label{subsec:safety}
% ─────────────────────────────────────────────────────────────────────────────

The domain papers show promising accuracy, but accuracy alone is not enough for a
clinical system. The system also has to be safe, reliable, and able to recover
from errors. Only a small number of reviewed papers focus directly on these
issues. Table~\ref{tab:tracker_safety} summarises the two most relevant papers.

MedSentry by Chen et al. studies adversarial safety in clinical multi-agent
systems \cite{Chen2025MedSentry}. The authors tested centralised, decentralised,
layered, and shared-pool topologies by adding one compromised agent and then
running 5{,}000 adversarial medical prompts. The centralised topology was the
most vulnerable because one compromised component could influence the whole
system. The decentralised topology was the most resilient. The study also showed
that simple safety filters could be bypassed, so agent isolation and prompt
purification are needed. Figure~\ref{fig:medsentry} shows the defence results.

EHRFlow by Wu et al. focuses on operational reliability instead of adversarial
attack \cite{Wu2024EHRFlow}. It uses four agents: a Coder Agent that writes
analysis code, an Executor Agent that runs it, a Debugger Agent that fixes errors,
and a Summariser Agent that turns outputs into readable findings. It achieved
higher task completion than single-agent systems on EHR analysis tasks such as
cohort selection, lab trend analysis, and outcome prediction. The main lesson for
this thesis is that failures should be handled inside the workflow before they
propagate to later agents.
