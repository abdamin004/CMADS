\section{Experimental Setup}
\label{sec:results_setup}
% ─────────────────────────────────────────────────────────────────────────────

\paragraph{Cohort.} The evaluation cohort consists of 160 Gold-layer
patients selected by the deterministic eligibility rules and the LLM-based
detectability verifier of Section~\ref{sec:llm_verifier}, and run end-to-end
through the seven-agent pipeline. These patients cover
the target disease groups used in the thesis: ischemic heart disease (IHD),
chronic congestive heart failure (CHF), essential hypertension, type-2
diabetes mellitus (T2DM), end-stage renal disease together with chronic
kidney disease stages 2--3 (reported together as ESRD~/~CKD), and
metabolic syndrome~X. The CKD substages are separate SNOMED labels in
the data, but they share one NICE management pathway, so they are
grouped for reporting. The aggregate file shows the principal 160 cohort
contains ESRD, CKD stage 3, and CKD stage 2 only; no CKD stage 1
patients are present. The agents do not see
the ground-truth condition during inference; only the evaluator receives it.

\paragraph{Models and infrastructure.}
The main reasoning model is GPT-OSS-120B served through Groq. The evaluator is
Qwen3-32B, also served through Groq. Both are accessed through the provider
adapter described in Section~\ref{sec:env}. Qdrant is used for NICE guideline
retrieval and case-based memory. The data pipeline, prompt rendering, agent
orchestration, and evaluation scripts run on an Apple Silicon workstation. The
React + FastAPI doctor console is served locally on the same workstation.

\paragraph{Pipeline configuration.}
All runs use the default values in \texttt{src/config.py}: maximum diagnostic
rounds of 3, confidence threshold of 75, an outer per-agent execution budget
of 300 seconds, a 120-second slow-call warning threshold in the provider
adapter (logged rather than enforced as per-call cancellation), and capped
exponential retry. Prompt templates are loaded from
\texttt{prompts/\{agent\_id\}.yaml}. No prompt or threshold was tuned after
seeing the reported results. Run files are saved under
\texttt{data/gold/mas\_results\_*/}, with one folder per patient UUID. Each
folder contains one JSON file per agent and an \texttt{execution\_trace.json}
timeline. The metrics below are computed from those files.\footnote{The
headline outcomes in this section are computed from the principal
multi-level memory configuration on the 160-patient paired cohort,
whose per-patient outputs live in the three multi-level run directories
\texttt{data/gold/mas\_results\_improved\_b3/},
\texttt{data/gold/mas\_results\_improved\_50/}, and
\texttt{data/gold/mas\_results\_improved\_extra60/}. The paired memory
A/B in Section~\ref{sec:results_memory_ab} compares those same UUIDs
under the single-level baseline configuration, whose outputs are read
from \texttt{data/gold/mas\_results/} (the 65 overlap UUIDs from the
original baseline cohort) and
\texttt{data/gold/mas\_results\_paired95\_single\_level/} (the 95 UUIDs
re-run with \texttt{MEMORY\_ENABLED=false}). The single-LLM controlled
baseline in Section~\ref{sec:results_single_llm} writes to
\texttt{data/gold/mas\_results\_single\_llm\_baseline/}.}

% ─────────────────────────────────────────────────────────────────────────────
\section{Evaluation Metrics}
\label{sec:results_metrics}
% ─────────────────────────────────────────────────────────────────────────────

The evaluator produces five main values for each patient. \textbf{Match type}
is DIRECT, INDIRECT, or MISS. DIRECT means the target disease appears in the
differential as a clear match. INDIRECT means the system found a clinically
related disease. MISS means it did not find the target disease or an acceptable
proxy. \textbf{Rank-when-found} records where the matched disease appears when
the judge returns DIRECT or INDIRECT. \emph{Rank-1-when-found} is the share of
found cases where the match is ranked first. \textbf{Per-agent status} records
success, partial, error, or skipped in \texttt{execution\_trace.json}.
\emph{Partial} means the output was recovered after a validation issue.
\emph{Error} means the agent failed and downstream agents carried a
\texttt{null} value. \emph{Skipped} means the agent was intentionally bypassed,
as with Treatment Planning when the match is not DIRECT. \textbf{Per-agent
latency} is the wall-clock time for each agent call. For memory, the chapter
reports a paired controlled comparison on 160 identical patients run in each memory
setting and discusses cohort leakage as a limitation of interpreting memory
effects.

\paragraph{How rates are reported.}
All diagnostic outcomes are reported as percentages with the
underlying counts in parentheses, e.g. $76.9\,\%$ (123/160), so the
reader can see both the rate and the denominator that produced it.
Comparisons in this chapter are paired wherever possible: the memory
A/B (Section~\ref{sec:results_memory_ab}) and the single-LLM baseline
(Section~\ref{sec:results_single_llm}) both run two configurations on
the same patient set, so the comparison controls for cohort
composition. The detectability-gate check
(Section~\ref{sec:results_detectability_sensitivity}) is a single-arm
sensitivity sample on the rejected band of the verifier, reported as
a descriptive contrast with the admitted-cohort rate rather than as
an inferential test.

\paragraph{Why IHD lags the cohort.}
The IHD result ($51.9\,\%$ DIRECT on $n=27$) is the single largest
drag on the headline rate, and it is worth understanding the
mechanism. Real cardiology cases come with imaging signals --- ECG
ST-segment changes, regional wall-motion abnormalities on echo,
coronary calcium burden --- and with biomarker signals such as
troponin trajectories and BNP. None of these are present in the
Synthea Gold-layer evidence the pipeline receives: Synthea
emits SNOMED conditions, vitals, and a small set of laboratory
panels, but no imaging modalities and no high-sensitivity troponin
time series. The diagnostic agent therefore has to lean on the
cardiometabolic proxies it can see --- hypertension, dyslipidaemia,
and diabetes --- and frequently surfaces an IHD-adjacent term such as
``Atherosclerotic coronary artery disease with recent myocardial
infarction'' at rank one. The judge then classifies this as INDIRECT
for the broader Ischemic heart disease target, which is why the IHD
row has both a depressed DIRECT rate and an elevated INDIRECT rate
($29.6\,\%$). This is a data-modality gap, not a reasoning failure
--- adding an imaging-converter agent would lift IHD without
retraining the diagnostic core.

\subsection{Detectability-Gate Sensitivity}
\label{sec:results_detectability_sensitivity}
% ─────────────────────────────────────────────────────────────────────────────

The 76.9\% DIRECT headline is evaluated on a cohort that has already passed
the LLM-based detectability verifier described in
Section~\ref{sec:llm_verifier}, which admits only patients with a
confidence score of at least 80. This is a deliberate data-quality choice,
not a hidden filter, but it does mean the reported rate is conditional on
the gate. To quantify how much of the headline depends on this conditioning,
a sensitivity sample was drawn from the rejected band of the verifier
output (confidence 60--79), stratified evenly between the two ten-point
sub-bands and seeded so the selection is reproducible
(\texttt{scripts/sample\_rejected.py}, seed 42). The selected patients have
valid Gold-layer evidence and a Synthea ground-truth label; only the
detectability verifier judged them as borderline rather than clearly
diagnosable.

These thirty patients were then run end-to-end through the same seven-agent
pipeline, with results persisted to
\texttt{data/gold/mas\_results\_detectability\_sensitivity/}, and judged by
the same Qwen3-32B evaluator used for the main cohort. The intent is to
estimate the DIRECT rate the system would have achieved on cases the gate
currently excludes and to contrast it with the admitted-cohort rate; this
is a single-arm sensitivity sample, not a paired comparison, so it is
read here as a descriptive contrast on patient detectability rather than
as an inferential test.

\paragraph{Sensitivity result.}
On the thirty rejected-band patients, the system recorded a DIRECT match
in $13.3\,\%$ of cases (4/30), an INDIRECT match in $56.7\,\%$ (17/30),
and a MISS in $30.0\,\%$ (9/30). Compared with the $76.9\,\%$ (123/160)
DIRECT rate on the accepted cohort, this is a drop of
$63.6$ percentage points --- a roughly five-fold gap between the two
conditions, consistent with the verifier's role as a hard
data-quality gate.

\paragraph{Reading the result.}
The gate is doing real selection work: the $76.9\,\%$ headline is
conditional on detectability rather than a population-level
capability, and the gap between the two conditions is large. The
interpretation throughout this chapter is therefore that CMADS
produces a $76.9\,\%$ DIRECT rate \emph{on patients the detectability
verifier admits}, and a $13.3\,\%$ DIRECT rate on the rejected band of
the verifier. The INDIRECT rate on the rejected band is comparatively
high ($56.7\,\%$), which suggests the pipeline still surfaces
clinically related findings on borderline cases even when it fails
to identify the exact target disease. The DIRECT gap across the gate
also acts as a post-hoc consistency check on the verifier itself:
the verifier's confidence score is calibrated against the same
outcome the agent pipeline is later evaluated on, which is the
behaviour the gate was designed to produce. The raw counts are
persisted to
\texttt{data/\allowbreak gold/\allowbreak mas\_\allowbreak results\_\allowbreak detectability\_\allowbreak sensitivity/\allowbreak sensitivity\_\allowbreak summary.json}
for reproducibility.

100\% success and Treatment Planning matches its DIRECT-gated design.

file at all; in these cases the pipeline reached Stage~5 (LLM
Evaluator) but exited before Stage~6 wrote a file, either through the
SkipAgentException path (the structured skip used for non-DIRECT
matches in current code) or through a pre-telemetry transient that no
longer occurs on re-runs. A small number of pre-telemetry MISS /
INDIRECT runs hold non-skip placeholders rather than the structured
skip described in Section~\ref{sec:agent_tx}; those are stale
artifacts from earlier code, not evidence of a treatment-gate
failure.

Diagnostic Reasoning is the slowest stage, with a mean runtime of about
100 seconds and a 95th percentile near 133 seconds. This is expected because
the agent uses several LLM calls and may run more than one reasoning round.
Most other agents finish in under one minute on average. The LLM Evaluator is
fastest because it performs a short classification task. The reliability table
also shows the value of graceful degradation: when a Stage~1 output was only
partial, the later agents still ran and produced a final diagnosis. No patient
run failed completely because of an upstream agent error.

\section{Adaptive Reasoning and Reviewer/Refiner Effects}
\label{sec:results_adaptive}
% ─────────────────────────────────────────────────────────────────────────────

Two design choices can be checked from the run files: the adaptive diagnostic
loop and the non-destructive Reviewer-Refiner pattern from
Section~\ref{sec:agent_refiner}.

The Reviewer-Refiner pattern had a visible effect. A programmatic
comparison of the rank-1 diagnosis between
\texttt{diagnostic\_\allowbreak reasoning.json} and
\texttt{final\_\allowbreak diagnosis.json} across the full cohort
(\texttt{scripts/refiner\_changed\_primary.py}) finds that the
Diagnostic Refiner changed the primary diagnosis originally produced
by the Diagnostic Reasoning agent in \textbf{93 of 160 runs (58.1\,\%)}.
This happened because the Refiner does not
delete the original diagnostic output; it can change the final primary while
keeping the earlier output available for audit. The Reviewer also often flagged
anchoring on one strong lab value, such as creatinine pushing the agent toward
ESRD when the full patient history supported another primary condition. The
Refiner then re-weighted the differential using that critique.

The Diagnostic Reasoning agent also used its bounded self-critique loop. The
loop stops when confidence reaches 75 or after three rounds. In the memory runs
where \texttt{session\_memory.json} is available, most cases stopped after one
round, about a third stopped after two rounds, and the rest used all three
rounds. This saves time on easier cases and leaves more reasoning budget for
harder ones.

\section{Multi-Level Memory A/B Study}
\label{sec:results_memory_ab}
% ─────────────────────────────────────────────────────────────────────────────

The memory subsystem is evaluated as a paired controlled experiment
on the same 160 patients from Section~\ref{sec:results_setup}, run
twice under \texttt{MEMORY\_ENABLED=false} and
\texttt{MEMORY\_ENABLED=true}. The controlled variable is the memory
configuration; patient identity, prompts, evaluator, and model are
held fixed across arms. The persisted per-patient outcomes and pair
table are at \texttt{data/gold/paired\_160\_mcnemar.json}.

On the same 160 patients, the DIRECT rate under the multi-level
configuration is \textbf{76.9\,\%} (123/160) against
\textbf{53.8\,\%} (86/160) for the single-level baseline ---
a $+23.1$ percentage-point advantage on the paired controlled
comparison.

The Found rate also rises in the multi-level configuration ---
\textbf{94.4\,\%} (151/160) against \textbf{92.5\,\%} (148/160) for
the single-level baseline, a $+1.9$ percentage-point gain on the
same patients --- with a matching $-1.9$ percentage-point drop on
MISS ($5.6\,\%$ vs.\ $7.5\,\%$). The substantive contribution of the
multi-level memory configuration is therefore on both the primary
diagnosis and differential breadth, with the broader-differential
effect documented in Section~\ref{sec:results_qualitative} lifting
Found above what the single-level baseline achieves on the same
patients.

The earlier descriptive 205-vs-100 unpaired aggregate is retired.
The apparent --- and incidentally inverted --- DIRECT gap in that
unpaired comparison is a cohort-selection artifact: the multi-level cohort
(batches 3, 4, and the supplementary extra-60 fills from batches 1
and 5) has a different disease distribution than the patients in
\texttt{mas\_results/} that produced the headline number in
Section~\ref{sec:results_e2e}. When patient identity is held
constant, the principal multi-level memory configuration wins by
$+23.1$ percentage points on DIRECT against the single-level
baseline ($76.9\,\%$ vs.\ $53.8\,\%$, 123/160 vs.\ 86/160) and adds
$+1.9$ percentage points on Found ($94.4\,\%$ vs.\ $92.5\,\%$). On
the paired test that earlier cohort-selection artifact disappears
and the full configuration's contribution is large and positive.

An intermediate configuration --- Tier-4 case-based memory only,
with the other three tiers disabled --- was also run during
development on a fifty-patient subset. Its result was ambiguous: the
DIRECT rate was lower than the memory-disabled configuration but the
rank-1-within-found rate was higher, which suggests case-based
retrieval alone introduces the differential broadening seen in the
full multi-level configuration with weaker re-ranking signal. The
ambiguity at this size is part of why a dedicated tier-by-tier
ablation is identified as future work in
Chapter~\ref{chap:conclusion}.

The leakage risk is important. The case-based store does contain
patients used for evaluation, but retrieval explicitly filters out
the patient's own UUID and there are no near-duplicate inputs in the
Synthea-generated cohort beyond what disease-family similarity
naturally produces; the paired test on the same 160 patients in
both arms removes any cohort-composition contribution to the
comparison. The remaining interpretive caveat is the one above: the
mechanism we see in the data is differential broadening, not a
proven primary-diagnosis accuracy gain from memory.

\paragraph{Scope of the comparison.}
The headline number measures the four tiers acting together; this
thesis does not isolate the contribution of any single tier. Future
work should run one-tier-out variants on the same 160-patient cohort
to identify whether the gain is driven primarily by case-based
retrieval, episodic summaries, or the combination. The system records
every memory operation in a typed trace, so the ablation is
straightforward to instrument.

\section{Model Selection Pilot}
\label{sec:results_models}
% ─────────────────────────────────────────────────────────────────────────────

A paired model comparison on a fixed twenty-patient subset ran the
same patients, prompts, evaluator, and memory setting through two
diagnostic models: GPT-OSS-120B served via Groq and Med42-70B served
locally through Ollama. The lead finding is wall-clock: GPT-OSS-120B
on Groq runs roughly $13\times$ faster than Med42-70B locally
(median $\sim$108\,s vs.\ $\sim$2\,000\,s per patient). On the same
twenty patients it also delivers a higher DIRECT rate
($40\,\%$, 8/20 vs.\ $25\,\%$, 5/20). For the doctor's runtime
workflow the speed matters as much as the accuracy: a clinician
cannot wait 30 minutes per patient for a second opinion.
Table~\ref{tab:model_comparison} summarises the result.

this pipeline, model quality and inference speed both matter because
latency adds up across seven agents and multiple diagnostic rounds.

\section{Comparison with the Literature}
\label{sec:results_literature}
% ─────────────────────────────────────────────────────────────────────────────

The papers reviewed in Chapter~\ref{chap:background} provide context for these
results, but direct accuracy comparison is difficult. The studies use different

Compared with MDAgents and MAC, this system uses the same broad idea of
specialised agents working on one clinical task. The difference is that CMADS
uses a fixed LangGraph workflow with parallel Stage~1 execution, a diagnostic
critique loop, and a non-destructive Reviewer-Refiner step. It also adds the
four-tier memory system and reports a paired 160-patient memory A/B that
controls for cohort composition by holding patient identity constant across
arms.

Compared with ZODIAC and ClinicalLab, a direct accuracy comparison would be
unfair because the cohorts are different. ZODIAC uses real cardiology data.
ClinicalLab uses real cases across eleven departments. This thesis uses
synthetic Synthea patients across several disease groups. The strength of this
setup is control: the same patients, prompts, and evaluator can be reused to
study design choices such as memory and model choice.

Compared with RareAgents, this work supports a similar lesson: workflow and
supporting tools can matter as much as the base model. RareAgents showed that
an open-source model with memory and tools can match or exceed GPT-4o on
rare-disease diagnosis. In this thesis, GPT-OSS-120B inside the seven-agent
workflow recorded both a higher DIRECT rate and a much lower per-patient
latency than the locally served Med42-70B model on the controlled twenty-patient
subset, with the wall-clock gap as the lead finding. The additional point
here is the transparent memory comparison, including the cohort-leakage
caveat, which is not usually reported in memory-augmented clinical agent
papers. The intent across this section is to position CMADS \emph{alongside}
the published literature rather than to claim a head-to-head win on any
single benchmark: the cohorts and metrics differ in ways that make a
leaderboard reading inappropriate.

\subsection{Revisiting the Optimisation Paradox}
\label{sec:results_paradox}

Bedi et al.~\cite{Bedi2025OptParadox} report what they call the
``Optimisation Paradox'' in clinical multi-agent LLM systems. On
2{,}400 MIMIC-IV-CDM cases, their best single-agent configuration
reached $67.7\,\%$ diagnostic accuracy and outperformed both their
homogeneous and heterogeneous multi-agent variants on the same
cases. Read literally, this suggests that more agents do not help
and may hurt. The CMADS evaluation reported in
Section~\ref{sec:results_single_llm} appears to contradict that
result --- the seven-agent pipeline beats a single-prompt baseline
by $+33.8$ percentage points on DIRECT ($73.8\,\%$ vs.\ $40.0\,\%$,
118/160 vs.\ 64/160) on the same 160 patients with the same
reasoning model.

Three reconciliation points are worth stating. First, the baseline
to which Bedi et al.\ compare is not the same baseline used here:
their ``single agent'' was already a sophisticated chain-of-thought
configuration with structured reasoning, while the CMADS comparison
is against a deliberately simpler single-call baseline with no
explicit chain-of-thought scaffolding. The CMADS lift therefore
includes the contribution of any reasoning scaffolding, not only
the contribution of multi-agent coordination. Second, the
evaluation rubrics differ: Bedi et al.\ measure against the
discharge diagnosis derived from real MIMIC notes with
clinician-in-the-loop adjudication, whereas the CMADS evaluation
measures against the Synthea ground-truth label using the
three-label LLM-as-judge rubric documented in
Section~\ref{sec:evaluation}. Two different operational definitions
of ``correct'' will not produce comparable absolute accuracy
numbers across studies. Third, and most importantly, the
multi-agent variants Bedi et al.\ benchmarked lacked the
specific orchestration patterns that drive the CMADS gain --- the
non-destructive Reviewer-Refiner pattern reported in
Section~\ref{sec:results_adaptive} (where the Reviewer never
deletes a hypothesis but the Refiner re-merges with explicit
verified/refuted/uncertain flags), and the four-tier memory
subsystem reported in Section~\ref{sec:results_memory_ab} (where
the case-based prior contributes the $+23.1$ percentage-point
DIRECT lift on the paired comparison). On the present evidence the
paradox is not refuted in general --- adding undifferentiated
agents to a sophisticated reasoner may well still hurt, as Bedi et
al.\ argue. What this thesis identifies is which specific
orchestration patterns appear to escape it.

\paragraph{Takeaway.} The Optimisation Paradox is reconciled rather
than refuted: the CMADS gain is concentrated in two orchestration
patterns (non-destructive Reviewer-Refiner, four-tier memory) that
were not present in the multi-agent variants Bedi et al.\ tested.

\section{Single-LLM Controlled Baseline}
\label{sec:results_single_llm}
% ─────────────────────────────────────────────────────────────────────────────

A natural question is how much of the headline accuracy comes from
the multi-agent orchestration itself as opposed to the underlying
language model. To answer it directly, the same 160-patient principal
cohort (Section~\ref{sec:results_e2e}) was re-evaluated under a
single-LLM-call baseline. For each patient, one prompt is constructed
from the same Gold-layer EHR and lab inputs the multi-agent pipeline
sees; the prompt asks the model to produce a ranked top-five
differential in a fixed five-line format. No agent orchestration is
present, no Reviewer/Refiner step, no memory subsystem, no NICE
retrieval. The same evaluator model (Qwen3-32B) then scores the
resulting differential against the hidden Synthea ground truth using
the same three-label rubric.

\textbf{The single-LLM baseline uses the same reasoning model as the
multi-agent pipeline --- GPT-OSS-120B served through Groq at
temperature 0.1.} The judge model (Qwen3-32B) is also held constant
across both arms. Holding the model identical across arms is what
lets the observed difference be attributed to the orchestration
rather than to a model swap.
\texttt{scripts/single\_llm\_baseline.py} pairs the two arms by UUID
and writes the per-patient outcomes; the persisted output is at
\texttt{data/gold/mas\_results\_single\_llm\_baseline/paired\_vs\_7agent.json}.

result directories), which has a slightly different disease
composition --- hence $76.9\,\%$ versus $73.8\,\%$ DIRECT.

On the same 160 patients, the multi-agent orchestration buys a
$+33.8$ percentage-point advantage on top-1 primary-diagnosis
accuracy over the single-call baseline ($73.8\,\%$ vs.\ $40.0\,\%$,
118/160 vs.\ 64/160) at identical patient data with the same model.

The Found rate moves in the same direction: $88.1\,\%$ (141/160) for
the multi-agent pipeline against $68.1\,\%$ (109/160) for the
single-call baseline, a $+20.0$ percentage-point gain in recall. The
single-call baseline loses on both axes; the multi-agent pipeline
does not buy precision at the cost of recall, it buys both.

The mechanism is visible in the qualitative case walkthroughs in
Section~\ref{sec:results_qualitative}. In Case~1, the single LLM call
commits to ``Acute non-ST elevation myocardial infarction'' for a
patient whose ground truth is essential hypertension; the multi-agent
Reviewer/Refiner step downweights that hypothesis after the Lab
Interpreter flags consistently elevated blood pressure with no
troponin trajectory. The single-call run cannot benefit from this
because no second pass exists.

The wall-clock cost of the multi-agent advantage is
non-trivial. The single-call baseline runs at approximately
$5$ seconds per patient against approximately $113$ seconds per
patient for the seven-agent pipeline --- a 22$\times$ speed
disadvantage for the orchestration. This is the practical trade-off:
$+33$ percentage points on DIRECT and $+19$ percentage points on
Found, for $22\times$ more wall-clock and a comparable multiple in
LLM call volume.

\paragraph{Where single-LLM wins, where CMADS wins.}
The single-prompt baseline is all-or-nothing: when it produces the
right answer at all, it is slightly more likely to be at rank one
($66.1\,\%$ Rank-1-within-found, $72/109$, versus $58.9\,\%$ for
CMADS, $83/141$). This is the single-LLM's local advantage --- a
sharper top guess on the cases it can solve. CMADS, however, surfaces
the correct condition somewhere in its top-five differential in
$88.1\,\%$ of cases against $68.1\,\%$ for the single-call baseline,
a $+20.0$ percentage-point gap in recall on the same patients. The
multi-agent pipeline is therefore slightly less likely to nail rank
one when both arms find the target, but dramatically more likely to
surface the target at all (within ranks one to five). For a doctor
reading the differential as a second opinion, this is the trade that
matters: a single LLM is overconfident-at-rank-one but blind in
$32\,\%$ of cases; CMADS is slightly less certain at its top pick but
blind in only $12\,\%$. The cost of this recall gain is the
$22\times$ wall-clock penalty ($1.9$\,s versus $129.7$\,s per
patient). \textbf{Takeaway:} the single-LLM is better when you only
read the first line; the multi-agent system is better when you read
the top-5 differential as intended.

\subsection{Doctor (runtime) journey}
\label{subsec:results_dashboard_doctor}

The Doctor journey is for a clinician with a patient in front of them.
The entry view offers two ways in: a \emph{Known patient} tab takes a

Gold-layer record, and a \emph{Build / clone a patient} tab opens a

\subsection{Researcher (statistics) journey}
\label{subsec:results_dashboard_researcher}

The Researcher journey is for a reviewer or examiner inspecting past runs.
The Overview tab renders the headline accuracy KPIs as large numerals ---
patients reviewed, system Found rate, median runtime, and an interactive
Precision-at-K card --- and a collapsible breakdown by rank bucket and
per ground-truth disease beneath, all sourced live from the MongoDB
\texttt{agent\_runs} collection on the 160-patient multi-level cohort
union (the same numbers reported in Section~\ref{sec:results_e2e}). The
Memory A/B tab puts the single-level baseline arm in neutral grey above
the principal multi-level configuration in green, so the directional
improvement is visible at a glance before the reader scrolls to the
McNemar contingency underneath. The Patients tab opens with a static
data-structure explainer so the reviewer knows exactly what each of the
seven agents is fed before drilling into any single patient; clicking a
patient swaps the right panel for the ranked differential, agent
narratives, treatment plan, and similar-prior-cases panel.

Five tabs sit above the main panel:
\textbf{Overview} (system-accuracy KPIs on the principal multi-level
configuration, with a Precision-at-K interactive card and an expandable
breakdown by rank and per-disease, all served from the multi-level cohort
union of \texttt{mas\_results\_improved\_b3/\_50/\_extra60/});
\textbf{Memory A/B} (single-level baseline versus the principal
multi-level configuration on the same 160 paired patients --- per-arm KPI
strips, side-by-side colour-coded delta table, and the 2$\times$2
DIRECT-classification contingency that drives the exact McNemar test of
Section~\ref{sec:results_memory_ab});
\textbf{Model} (GPT-OSS 120B head-to-head against Med42 70B on the
twenty-patient pilot of Section~\ref{sec:results_models});
\textbf{MAS vs single-LLM} (the controlled-baseline comparison of
Section~\ref{sec:results_single_llm});
and \textbf{Patients}, the per-patient drill-down view that exposes the
agent narrative, ranked differential, treatment plan, and the top-$K$
similar prior cases from Tier-4 case-based memory for any selected
patient.

The five comparison tabs share one visual language: each surface opens
with a one-sentence framing, then a side-by-side arm comparison with the
baseline arm in neutral grey and the principal configuration in green to
mark the recommended read, then the same coloured delta table format
(green when the principal configuration wins on the metric's clinical
direction, red when the baseline wins). The Patients tab additionally
hosts the data-structure explainer (a static description of what the
seven agents see for each patient) and the per-agent prompt-template
viewer, so a reviewer can verify exactly what every agent was asked to do
without leaving the dashboard.

The combined effect is that one application carries the system from
``run it on this patient'' to ``audit it across every past patient with
the same accuracy table the thesis reports'', and a viva examiner can
move from a headline percentage in this chapter to the patient-level
evidence behind it in two clicks. The hidden ground truth is never
shown so the console reads as a clinician-facing review surface rather
than a spoiler tool.
