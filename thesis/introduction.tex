\section{Motivation}
\label{sec:motivation}
% -----------------------------------------------------------------------------

Clinical diagnostic error is a persistent source of patient harm. A large
outpatient-care review estimated that around five per cent of United States
adults experience a diagnostic error in any given year~\cite{Singh2014DiagnosticErrors},
and a follow-up 2024 analysis attributed approximately 795{,}000 deaths or
permanent disabilities annually in the United States alone to diagnostic
error~\cite{NewmanToker2024Burden}. The clinician's task has also grown heavier:
a time and motion study found that physicians spend nearly two hours on the
electronic health record for every hour of direct patient
contact~\cite{Sinsky2016Allocation}, leaving less room to synthesise the
conditions, medications, laboratory trends, and visit notes that bear on a
diagnostic decision. Clinical decision support has been studied for many years
as one response to this pressure, but the gap between research benchmarks and
bedside use remains wide.

Diagnosis is difficult because a doctor usually has to connect many pieces of
evidence at the same time. A patient record can include old conditions,
medications, vital signs, laboratory results, and notes from different visits.
Some findings point in different directions, and the doctor still has to decide
which diagnoses are most likely and what should be done next.

Large language models (LLMs) are useful for this type of work because they can
read long text, summarise evidence, and explain their reasoning in natural
language. Recent studies show that LLM-based systems can perform well on medical
question-answering tasks and other controlled clinical benchmarks
\cite{Abbasian2024openCHA,Tang2024MedAgents}. However, good benchmark scores do
not automatically make a system useful in a clinical workflow. A single LLM call
can miss important evidence, copy a wrong assumption from the prompt, or produce
a confident answer without checking it. Prior work also shows that medical LLM
errors often come from missing domain knowledge and from reasoning biases such as
anchoring and confirmation bias \cite{Tang2024MedAgents,Ke2024CognitiveBias}.

Multi-agent systems are one way to reduce these problems. Instead of asking one
model to do every task, the system splits the work between agents with different
roles. One agent can analyse the EHR, another can interpret labs, another can
build the differential diagnosis, and another can review the result. This is
closer to how complex cases are often discussed by clinical teams. Recent
systems such as MDAgents, ZODIAC, ClinicalLab, the MAC Framework, and
MDTeamGPT show that multi-agent LLM workflows can improve medical reasoning in
specific settings \cite{Kim2024MDAgents,Zhou2024ZODIAC,Yan2024ClinicalLab,MAC2025npj,Chen2025MDTeamGPT}.

The main problem is not only the strength of the model. It is also the way the
agents are connected. If agents pass weak outputs to each other, repeat the same
mistake, or overwrite earlier reasoning, the final answer can still be unsafe or
hard to inspect. Bedi et al. describe this as an optimisation problem in which
the best individual components do not always make the best system when they are
combined poorly \cite{Bedi2025OptParadox}. This thesis starts from that point. It
builds and evaluates a multi-agent clinical decision support system that uses
synthetic patient records, shared memory, guideline retrieval, and a dashboard
that lets a human reviewer inspect how the agents reached their answer.

\section{Key Terms and Definitions}
\label{sec:terms}
% -----------------------------------------------------------------------------

The thesis uses a number of technical terms repeatedly. The meanings below are
the meanings used in this project.

\begin{description}

  \item[\textbf{Large Language Model (LLM).}] A model that reads a prompt and
    generates text. In this thesis GPT-OSS-120B is used for most agent reasoning
    through Groq, while Qwen3-32B is used as the evaluation judge.

  \item[\textbf{Multi-Agent System (MAS).}] A system where several specialised
    agents solve one larger task together instead of using one model for the
    whole task \cite{Kim2024MDAgents}.

  \item[\textbf{Agent.}] In this project, an agent is one step in the pipeline.
    It has a prompt, calls an LLM through the provider adapter, returns a
    structured Pydantic output, and writes its result to shared state.

  \item[\textbf{Orchestrator.}] The control layer that decides which agent runs
    next. The implementation uses a LangGraph \texttt{StateGraph}.

  \item[\textbf{Shared state and shared memory.}] The shared state carries the
    current patient data and all agent outputs during one run. The wider shared
    memory also stores events, disease-level summaries, guideline knowledge, and
    prior case information that can be used in later runs.

  \item[\textbf{Differential diagnosis.}] A ranked list of possible diagnoses
    that could explain the patient evidence. The system returns each diagnosis
    with a confidence estimate and supporting evidence.

  \item[\textbf{Synthea.}] An open-source generator of synthetic patient records.
    In this thesis it is the source of the patient data and the hidden
    ground-truth disease labels.

  \item[\textbf{FHIR R4.}] The JSON-based healthcare data standard used by
    Synthea to export patients, encounters, observations, and conditions.

  \item[\textbf{OMOP CDM v5.4.}] A relational healthcare data model used in the
    Silver layer to normalise the Synthea data.

  \item[\textbf{Bronze, Silver, and Gold layers.}] The three data layers used in
    the project. Bronze stores raw FHIR data, Silver stores cleaned OMOP tables,
    and Gold stores per-patient EHR and lab case files used by the agents.

  \item[\textbf{Retrieval-Augmented Generation (RAG).}] A method where the model
    receives retrieved source material before answering. Here, the Treatment
    Planning agent retrieves NICE guideline content from Qdrant.

  \item[\textbf{LLM-as-Judge.}] An evaluation method where a separate LLM checks
    the system output against the hidden reference answer.

  \item[\textbf{DIRECT / INDIRECT / MISS.}] The three evaluation labels used in
    this thesis. DIRECT means the target disease is found clearly. INDIRECT means
    the system found a clinically related condition. MISS means it did not find
    the target disease or an acceptable proxy.

  \item[\textbf{Rank-1-when-found.}] When the system finds the correct or related
    disease, this metric checks how often that disease appears first in the
    ranked differential.

  \item[\textbf{Cohort leakage.}] A risk in memory-based evaluation where the
    system looks better because it has already seen similar cases from the same
    test cohort. This thesis measures that risk with a cold-start comparison.

\end{description}

\section{Research Gap and Problem Statement}
\label{sec:problem}
% -----------------------------------------------------------------------------

The literature shows that multi-agent clinical systems are promising, but four
problems are still important for a complete thesis implementation.

The first problem is \textbf{end-to-end coordination}. Many papers focus on a
single benchmark or one part of clinical reasoning. In this project, the system
must run from patient data preparation to EHR analysis, lab interpretation,
differential diagnosis, review, refinement, evaluation, and treatment planning.
This needs a graph that can run agents in the right order, allow parallel work
where possible, and continue safely if one agent fails.

The second problem is \textbf{useful disagreement between agents}. If all agents
simply agree with the first answer, the system does not really review itself.
Prior work shows that structured conflict resolution can improve diagnostic
accuracy \cite{Fan2024AIHospital,Wang2025Catfish}. In this thesis, the Clinical
Reviewer challenges the Diagnostic Reasoning agent, and the Diagnostic Refiner
uses that criticism without deleting the original diagnostic output. This keeps
the reasoning visible for inspection.

The third problem is \textbf{shared memory}. Many systems process every patient
as if no previous case existed. That makes evaluation simpler, but it does not
test whether the system can learn useful patterns across runs. At the same time,
memory can also create leakage if it stores information from the evaluation
cohort. This thesis implements multi-level memory, but it also tests memory with
a cold-start protocol so that the improvement is not accepted without checking
for leakage.

The fourth problem is \textbf{evaluation}. Medical question-answering benchmarks
are useful, but choosing one option from a list is not the same as generating a
ranked differential diagnosis from a patient record. For this reason, this thesis uses
an LLM-as-judge evaluator that compares the generated differential diagnosis with
the hidden Synthea disease label. The output is scored as DIRECT, INDIRECT, or
MISS, and the ranking is also checked when the target disease is found.

In simple terms, this thesis asks:

\begin{quote}
How can a multi-agent LLM system be designed so that it can process synthetic
longitudinal patient records, share memory between agents, review its own
diagnostic reasoning, and produce outputs that can be inspected and evaluated
without hiding the reasoning process?
\end{quote}

Two related topics are outside the main scope: defending the system against a
compromised agent \cite{Chen2025MedSentry}, and fully measuring the trade-off
between safety constraints and diagnostic accuracy \cite{Kim2025TAO,Wu2024EHRFlow}.
They are discussed again as future work in Chapter~\ref{chap:conclusion}.

\section{Aim and Research Question}
\label{sec:aim}
% -----------------------------------------------------------------------------

The aim of this thesis is to design, implement, and evaluate a multi-agent
clinical decision support system for synthetic patient records. The system should
produce a ranked differential diagnosis, allow agents to review and refine each
other's outputs, use shared memory in a controlled way, and present the reasoning
to a doctor through an inspection dashboard.

The main research question is:

\begin{quote}
Can a multi-agent LLM workflow produce clinically plausible differential
diagnoses from synthetic longitudinal patient records, and does multi-level
shared memory improve diagnostic accuracy compared with a single-level memory
setup when cohort leakage is controlled?
\end{quote}

The corresponding hypothesis is that multi-level shared memory broadens the
system's candidate differential without improving primary-diagnosis precision
once cohort leakage is controlled, and that a non-destructive Reviewer--Refiner
deliberation pattern is the practical mechanism that allows the system to
rewrite a flawed primary diagnosis while preserving the original reasoning for
audit. Figure~\ref{fig:intro_system} previews the system at a high level; the
detailed agent graph, shared-memory subsystem, and dashboard are unpacked in
Chapter~\ref{chap:methodology}.

The generated evaluation set contains 270 candidate patients from the Gold layer.
The results chapter reports the 160 patients that completed the full agent
pipeline and uses smaller controlled subsets for the memory A/B tests and
cold-start leakage checks.

\section{Objectives}
\label{sec:objectives}
% -----------------------------------------------------------------------------

The objectives of the thesis are:

\begin{itemize}

  \item Build a Synthea-based data pipeline that converts raw FHIR R4 records
  into Bronze, Silver, and Gold layers, with Gold EHR and laboratory case files
  for each selected patient.

  \item Create a target cohort from 1{,}000 generated patients and select a
  270-patient candidate evaluation set across the implemented disease groups.

  \item Implement a LangGraph multi-agent pipeline with EHR Analyst, Lab
  Interpreter, Diagnostic Reasoning, Clinical Reviewer, Diagnostic Refiner, LLM
  Evaluator, and Treatment Planning agents.

  \item Add a Reviewer-Refiner pattern where the reviewer challenges the
  diagnostic output and the refiner updates the final differential while keeping
  the earlier output available for audit.

  \item Implement multi-level shared memory, including working memory, episodic
  traces, semantic disease summaries, guideline retrieval, and case-based
  retrieval over prior patients.

  \item Ground treatment planning in NICE guideline documents retrieved from
  Qdrant, and run treatment planning only when the diagnostic evaluator returns a
  DIRECT match.

  \item Evaluate free-text differential diagnoses using a separate LLM judge with
  DIRECT, INDIRECT, and MISS labels, plus rank-1-when-found.

  \item Compare multi-level memory with a single-level memory setup and include a
  cold-start check to estimate cohort leakage.

  \item Build a Streamlit dashboard that allows a reviewer to choose a patient,
  view the agent outputs, inspect memory use, and read the final result in a
  doctor-facing format.

\end{itemize}

\section{Scope and Assumptions}
\label{sec:scope}
% -----------------------------------------------------------------------------

This thesis has several limits that are important for reading the results.

\textbf{Synthetic data only.} All patient records come from Synthea. No real
patient data or protected health information is used. This makes the work easier
to reproduce, but it also means the results depend on the quality and limits of
Synthea's disease models.

\textbf{Decision support only.} The system produces differential diagnoses,
evidence summaries, and treatment suggestions for human review. It is not
designed to make autonomous clinical decisions.

\textbf{Not a regulated medical device.} The implementation is a research
prototype. It has not been clinically validated, cleared by a regulator, or
tested prospectively in patient care.

\textbf{Bounded clinical coverage.} The implemented cohort focuses on these
target diagnoses and related disease groups: ischemic heart disease, chronic
congestive heart failure, essential hypertension, type-2 diabetes mellitus,
chronic kidney disease stage 2, chronic kidney disease stage 3, end-stage renal
disease, and metabolic syndrome X. The results should not be read as evidence
that the system works for diseases outside this set.

\textbf{Limited evaluation size.} The Gold layer contains 270 candidate
evaluation patients, but the completed empirical results in Chapter~\ref{chap:results}
are reported on 160 full pipeline runs. The smaller memory A/B studies are used
to study memory behaviour, not to claim final clinical performance.

\textbf{English-only reasoning.} The prompts, retrieved guidelines, and
dashboard text are in English. Non-English clinical text is outside the scope.

\section{Contributions}
\label{sec:contributions}
% -----------------------------------------------------------------------------

The main contributions of this thesis are:

\begin{enumerate}

  \item A working LangGraph clinical multi-agent pipeline with seven agents,
  parallel Stage~1 analysis, adaptive diagnostic reasoning, reviewer-based
  critique, diagnostic refinement, automated evaluation, and treatment planning.

  \item A multi-level shared-memory design for clinical agents, including working
  state, episodic traces, semantic disease summaries, guideline retrieval, and
  case-based recall of prior patients.

  \item A reproducible Synthea-to-Gold data pipeline that turns synthetic FHIR-R4
  records into structured EHR and lab case files with hidden ground-truth labels.

  \item A treatment planning step that retrieves NICE guideline material from
  Qdrant and uses it to produce guideline-grounded recommendations.

  \item An LLM-as-judge evaluation setup for free-text differential diagnoses,
  using DIRECT, INDIRECT, and MISS labels, rank-1-when-found, and a cold-start
  check for cohort leakage.

  \item A Streamlit doctor-facing dashboard that shows the patient case, each
  agent's output, the memory events, retrieved guideline evidence, and the final
  diagnosis in a format that is easier to review than raw JSON files.

\end{enumerate}

\section{Thesis Outline}
\label{sec:outline}
% -----------------------------------------------------------------------------

This thesis is divided into five chapters.

\textbf{Chapter~\ref{chap:background}: Background} reviews multi-agent LLM work
in clinical AI. It groups the papers by topic and uses them to explain the main
research gaps addressed by this project.

\textbf{Chapter~3: Methodology} explains how the system was built. It covers the
Synthea data pipeline, the Bronze/Silver/Gold data layers, the LangGraph agent
workflow, the agent designs, shared memory, guideline retrieval, model
configuration, and the evaluation method.

\textbf{Chapter~4: Results} reports the empirical findings. It presents the
160-patient completed cohort, per-disease results, per-agent reliability,
adaptive loop behaviour, memory A/B tests, model comparison, qualitative case
walk-throughs, and the dashboard.

\textbf{Chapter~5: Conclusion and Future Work} summarises what was achieved,
discusses the limits of the work, and outlines future steps such as real EHR
testing, broader disease coverage, stronger clinical review, and larger
memory-controlled experiments.
