\section{Motivation}
\label{sec:motivation}
% -----------------------------------------------------------------------------

Clinical diagnostic error remains a major source of preventable patient harm. A
large outpatient-care review estimated that around five per cent of United
States adults experience a diagnostic error in any given
year~\cite{Singh2014DiagnosticErrors}, and a 2024 analysis attributed
approximately 795{,}000 deaths or permanent disabilities each year in the United
States alone to diagnostic error~\cite{NewmanToker2024Burden}. At the same
time, the clinical workload around the electronic health record has grown: a
time and motion study found that physicians spend nearly two hours on the EHR
for every hour of direct patient contact~\cite{Sinsky2016Allocation}. This
leaves less time for the difficult part of diagnosis: connecting symptoms,
previous conditions, medications, laboratory trends, risk factors, and clinical
guidelines into one coherent judgement.

This is why clinical decision support remains an important research area.
Diagnosis is not a single-step task. It requires the clinician to compare
competing explanations, notice missing data, avoid premature closure, and decide
what evidence should be trusted. A patient record may contain clear signals, but
it may also contain old diagnoses, incomplete medication lists, abnormal values
that are not clinically meaningful, and findings that point in different
directions. Any useful clinical AI system therefore needs to support the
reasoning process, not only produce a final answer.

Large language models (LLMs) have renewed interest in this problem because they
can read long clinical text, summarise evidence, and explain a line of reasoning
in natural language. Recent studies show strong results on medical
question-answering tasks and controlled clinical benchmarks
\cite{Abbasian2024openCHA,Tang2024MedAgents}. However, benchmark performance
does not automatically translate into a safe clinical workflow. A single LLM
call is still a monolithic process: the same model reads all inputs, forms the
diagnosis, and presents the result without an independent reviewer inside the
workflow. Prior work shows that medical LLM errors often come from domain
knowledge gaps and from cognitive biases such as anchoring and confirmation
bias~\cite{Tang2024MedAgents,Ke2024CognitiveBias}. These are the same types of
failure that clinical decision support is meant to reduce.

Multi-agent systems provide a more suitable architecture for this setting.
Instead of asking one model to perform the whole clinical task, the work is
distributed across agents with separate responsibilities. One agent can analyse
the EHR, another can interpret laboratory trends, another can construct the
differential diagnosis, and a reviewer can challenge the result before a final
answer is saved. This resembles the way complex cases are often discussed by
clinical teams, where the value comes not only from one expert opinion but from
structured comparison and review. Recent systems such as MDAgents, ZODIAC,
ClinicalLab, the MAC Framework, RareAgents, and MDTeamGPT show that multi-agent
LLM workflows can improve medical reasoning in specific settings
\cite{Kim2024MDAgents,Zhou2024ZODIAC,Yan2024ClinicalLab,MAC2025npj,Chen2024RareAgents,Chen2025MDTeamGPT}.

The remaining challenge is not simply choosing a larger or more medical model.
It is designing the workflow that connects the agents. If agents pass weak
outputs to one another, silently agree with an early mistake, or overwrite
useful intermediate reasoning, the final result may look polished while still
being clinically wrong. Bedi et al. articulate this tension between
individually strong components and their coordination~\cite{Bedi2025OptParadox};
their framing motivates the design choices made here --- explicit shared
state, a non-destructive reviewer step, and a bounded diagnostic critique
loop --- but this thesis does not empirically reproduce their best-of-breed
versus coordinated comparison. Starting from that motivation, the thesis
designs and evaluates the Clinical Multi-Agent Decisioning System (CMADS),
a seven-agent clinical decision support pipeline built on synthetic patient
records, multi-level shared memory, NICE guideline retrieval, automated
evaluation, and a doctor-facing dashboard for inspecting how the result was
produced.

\section{Key Terms and Definitions}
\label{sec:terms}
% -----------------------------------------------------------------------------

The thesis uses a number of technical terms repeatedly. The meanings below are
the meanings used in this project.

\begin{description}

  \item[\textbf{Large Language Model (LLM).}] A model that reads a prompt and
    generates text. In this thesis GPT-OSS-120B is used for most agent reasoning
    through Groq, while Qwen3-32B is used as the evaluation judge.

  \item[\textbf{Multi-Agent System (MAS).}] A system where several specialised
    agents solve one larger task together instead of using one model for the
    whole task \cite{Kim2024MDAgents}.

  \item[\textbf{Agent.}] In this project, an agent is one step in the pipeline.
    It has a prompt, calls an LLM through the provider adapter, returns a
    structured Pydantic output, and writes its result to shared state.

  \item[\textbf{Orchestrator.}] The control layer that decides which agent runs
    next. The implementation uses a LangGraph \texttt{StateGraph}.

  \item[\textbf{Shared state and shared memory.}] The shared state carries the
    current patient data and all agent outputs during one run. The wider shared
    memory also stores events, disease-level summaries, guideline knowledge, and
    prior case information that can be used in later runs.

  \item[\textbf{Differential diagnosis.}] A ranked list of possible diagnoses
    that could explain the patient evidence. The system returns each diagnosis
    with a confidence estimate and supporting evidence.

  \item[\textbf{Synthea.}] An open-source generator of synthetic patient records.
    In this thesis it is the source of the patient data and the hidden
    ground-truth disease labels.

  \item[\textbf{FHIR R4.}] The JSON-based healthcare data standard used by
    Synthea to export patients, encounters, observations, and conditions.

  \item[\textbf{OMOP CDM v5.4.}] A relational healthcare data model used in the
    Silver layer to normalise the Synthea data.

  \item[\textbf{Bronze, Silver, and Gold layers.}] The three data layers used in
    the project. Bronze stores raw FHIR data, Silver stores cleaned OMOP tables,
    and Gold stores per-patient EHR and lab case files used by the agents.

  \item[\textbf{Retrieval-Augmented Generation (RAG).}] A method where the model
    receives retrieved source material before answering. Here, the Treatment
    Planning agent retrieves NICE guideline content from Qdrant.

  \item[\textbf{LLM-as-Judge.}] An evaluation method where a separate LLM checks
    the system output against the hidden reference answer.

  \item[\textbf{DIRECT / INDIRECT / MISS.}] The three evaluation labels used in
    this thesis. DIRECT means the target disease is found clearly. INDIRECT means
    the system found a clinically related condition. MISS means it did not find
    the target disease or an acceptable proxy.

  \item[\textbf{Rank-1-when-found.}] When the system finds the correct or related
    disease, this metric checks how often that disease appears first in the
    ranked differential.

  \item[\textbf{Cohort leakage.}] A risk in memory-based evaluation where the
    system looks better because it has already seen similar cases from the same
    test cohort. This thesis reports this risk explicitly when interpreting the
    aggregate memory comparison.

\end{description}

\section{Research Gap and Problem Statement}
\label{sec:problem}
% -----------------------------------------------------------------------------

The literature reviewed in Chapter~\ref{chap:background} shows that
multi-agent clinical systems are promising, but it also leaves a practical gap:
few systems join data preparation, diagnostic reasoning, memory, review,
treatment planning, evaluation, and clinician inspection into one reproducible
pipeline. Four problems are especially important for this thesis.

The first problem is \textbf{end-to-end coordination}. Many studies evaluate
one benchmark or one reasoning stage. A clinical decision support workflow has
to do more than that. It must move from patient data preparation to EHR
analysis, lab interpretation, differential diagnosis, review, refinement,
evaluation, and treatment planning. This requires an execution graph that can
run agents in the right order, allow parallel work where it is useful, and
continue safely when an agent produces a partial or invalid output.

The second problem is \textbf{meaningful disagreement between agents}. A
multi-agent system is weak if all agents simply confirm the first diagnosis.
Prior work shows that structured conflict resolution can improve diagnostic
accuracy \cite{Fan2024AIHospital,Wang2025Catfish}. In this thesis, the Clinical
Reviewer challenges the Diagnostic Reasoning output, and the Diagnostic Refiner
uses that critique to produce the final diagnosis. The original diagnostic
reasoning is not deleted, which keeps the decision path available for audit.

The third problem is \textbf{shared memory}. Many clinical agent systems treat
each patient as a completely new case. This makes evaluation easier, but it
does not test whether the system can reuse useful patterns across runs. Memory
can also create a false improvement if the system retrieves cases from the same
cohort that is later used for evaluation. For that reason, this thesis
implements multi-level memory, compares it against the memory-disabled setting
across all available runs, and discusses the cohort-leakage risk directly.

The fourth problem is \textbf{evaluation}. Medical multiple-choice benchmarks
are useful, but they are not the same as generating a ranked differential
diagnosis from a longitudinal patient record. The system must be judged on
whether it identifies the target disease, whether it finds a clinically related
condition, and where that condition appears in the ranked differential. This
thesis therefore uses a separate LLM-as-Judge evaluator that compares the
generated differential with the hidden Synthea disease label and assigns a
DIRECT, INDIRECT, or MISS verdict.

The research problem can therefore be stated as follows:

\begin{quote}
How should a team of specialised AI agents be coordinated so that their
combined clinical reasoning produces a diagnosis a physician could trust
and audit, rather than a polished but unverifiable answer from a single
black-box model?
\end{quote}

Two related topics are outside the main scope: defending the system against a
compromised agent \cite{Chen2025MedSentry}, and fully measuring the trade-off
between safety constraints and diagnostic accuracy \cite{Kim2025TAO,Wu2024EHRFlow}.
They are discussed again as future work in Chapter~\ref{chap:conclusion}.

\section{Aim and Research Question}
\label{sec:aim}
% -----------------------------------------------------------------------------

The aim of this thesis is to design, implement, and evaluate a multi-agent
clinical decision support system for synthetic patient records. The system is
intended to produce a ranked differential diagnosis, allow agent outputs to be
reviewed and refined, use shared memory in a controlled way, ground treatment
planning in guideline retrieval, and present the reasoning to a doctor through
an inspection dashboard.

The main research question is:

\begin{quote}
When clinical reasoning is split across a small team of specialised AI agents
that can review, critique, and remember each other's work, can they reach a
clinically plausible diagnosis --- and does giving them memory of past
patients actually help, or just add noise?
\end{quote}

The corresponding hypothesis is that a coordinated team of specialised
agents, with an explicit review step that can rewrite a flawed primary
diagnosis without erasing the earlier reasoning, produces clinically
plausible diagnoses more reliably than a single model alone; and that
shared memory of past patients broadens the differential the system
considers without making the top diagnosis more accurate. Figure~\ref{fig:intro_system} previews the system at a high level; the
detailed agent graph, shared-memory subsystem, and dashboard are unpacked in
Chapter~\ref{chap:methodology}.

filters described in Section~\ref{sec:llm_verifier}. The memory comparison
additionally uses all available unique runs within each memory setting.

\section{Objectives}
\label{sec:objectives}
% -----------------------------------------------------------------------------

The objectives of the thesis are:

\begin{itemize}

  \item \textbf{Build the clinical data pipeline.} Convert Synthea FHIR R4
  records into Bronze, Silver, and Gold layers, with Gold EHR and laboratory
  case files for each selected patient.

  \item \textbf{Construct the evaluation cohort.} Filter a Synthea-generated
  patient pool with deterministic eligibility rules and an LLM-based
  detectability verifier to yield a 160-patient evaluation cohort across the
  implemented disease groups.

  \item \textbf{Implement the multi-agent workflow.} Build a LangGraph pipeline
  with EHR Analyst, Lab Interpreter, Diagnostic Reasoning, Clinical Reviewer,
  Diagnostic Refiner, LLM Evaluator, and Treatment Planning agents.

  \item \textbf{Support structured clinical review.} Add a
  Reviewer--Refiner pattern where the reviewer challenges the diagnostic output
  and the refiner updates the final differential while keeping the earlier
  output available for audit.

  \item \textbf{Implement multi-level shared memory.} Store working state,
  episodic traces, semantic disease summaries, guideline knowledge, and
  case-based retrieval over prior patients.

  \item \textbf{Ground treatment planning in guidelines.} Retrieve NICE
  guideline material from Qdrant and run treatment planning only when the
  diagnostic evaluator returns a DIRECT match.

  \item \textbf{Evaluate free-text diagnoses.} Use a separate LLM judge with
  DIRECT, INDIRECT, and MISS labels, plus rank-1-when-found.

  \item \textbf{Measure the effect of memory.} Compare multi-level memory with
  a single-level setup across all available runs and report the cohort-leakage
  risk as a limitation of the comparison.

  \item \textbf{Build reviewer-facing interfaces.} Provide a Streamlit
  dashboard and a doctor console that allow a reviewer to choose a patient,
  inspect agent outputs and memory use, and read the final result in a
  doctor-facing format.

\end{itemize}

\section{Scope and Assumptions}
\label{sec:scope}
% -----------------------------------------------------------------------------

This thesis has several limits that are important for reading the results.

\textbf{Synthetic data only.} All patient records come from Synthea. No real
patient data or protected health information is used. This makes the work easier
to reproduce, but it also means the results depend on the quality and limits of
Synthea's disease models.

\textbf{Decision support only.} The system produces differential diagnoses,
evidence summaries, and treatment suggestions for human review. It is not
designed to make autonomous clinical decisions.

\textbf{Not a regulated medical device.} The implementation is a research
prototype. It has not been clinically validated, cleared by a regulator, or
tested prospectively in patient care.

\textbf{Bounded clinical coverage.} The implemented cohort focuses on these
target diagnoses and related disease groups: ischemic heart disease, chronic
congestive heart failure, essential hypertension, type-2 diabetes mellitus,
chronic kidney disease stage 2, chronic kidney disease stage 3, end-stage renal
disease, and metabolic syndrome X. The results should not be read as evidence
that the system works for diseases outside this set.

\textbf{Limited evaluation size.} The empirical results in
Chapter~\ref{chap:results} are reported on 160 Gold-layer pipeline runs.
The smaller memory A/B studies are used to study memory behaviour, not to
claim final clinical performance.

\textbf{English-only reasoning.} The prompts, retrieved guidelines, and
dashboard text are in English. Non-English clinical text is outside the scope.

\section{Contributions}
\label{sec:contributions}
% -----------------------------------------------------------------------------

The main contributions of this thesis are:

\begin{enumerate}

  \item A working LangGraph clinical multi-agent pipeline with seven agents,
  parallel Stage~1 analysis, adaptive diagnostic reasoning, reviewer-based
  critique, diagnostic refinement, automated evaluation, and treatment planning.

  \item A multi-level shared-memory design for clinical agents, including working
  state, episodic traces, semantic disease summaries, guideline retrieval, and
  case-based recall of prior patients.

  \item A reproducible Synthea-to-Gold data pipeline that turns synthetic FHIR-R4
  records into structured EHR and lab case files with hidden ground-truth labels.

  \item A treatment planning step that retrieves NICE guideline material from
  Qdrant and uses it to produce guideline-grounded recommendations.

  \item An LLM-as-judge evaluation setup for free-text differential diagnoses,
  using DIRECT, INDIRECT, and MISS labels, rank-1-when-found, and an aggregate
  memory comparison with explicit cohort-leakage caveats.

  \item A Streamlit doctor-facing dashboard that shows the patient case, each
  agent's output, the memory events, retrieved guideline evidence, and the final
  diagnosis in a format that is easier to review than raw JSON files.

\end{enumerate}

\section{Thesis Outline}
\label{sec:outline}
% -----------------------------------------------------------------------------

This thesis is divided into five chapters.

\textbf{Chapter~\ref{chap:background}: Background} reviews multi-agent LLM work
in clinical AI. It groups the literature by topic, including foundation
frameworks, coordination patterns, debate and review mechanisms, clinical
deployments, safety, and evaluation. The chapter is used to justify the design
choices made later in the system.

\textbf{Chapter~3: Methodology} explains how CMADS was built. It covers the
Synthea data pipeline, Bronze/Silver/Gold data layers, Gold case construction,
LangGraph workflow, agent blueprint, seven specialised agents, multi-level
shared memory, NICE guideline retrieval, model configuration, evaluation method,
and implementation stack.

\textbf{Chapter~4: Results} reports the empirical findings. It presents the
160-patient completed cohort, end-to-end diagnostic outcomes, per-disease
results, per-agent reliability, adaptive reasoning behaviour, memory comparison,
model comparison, literature comparison, qualitative case walkthroughs, and the
doctor-facing dashboard.

\textbf{Chapter~5: Conclusion and Future Work} summarises the thesis
contributions, explains the limits of the current prototype, and outlines future
steps such as real EHR testing, broader disease coverage, prospective clinical
review, and larger memory-controlled experiments.
