03 · The problem

The old shared state hid the reasoning chain the agents needed to challenge each other.

The Diagnostic agent runs an adaptive critique loop. The Reviewer's job is to challenge the differential it produces — but it could only see the final JSON. The path was gone.

  • Round 1 — confidence 60. anchored on a single lab finding.
  • Round 2 — confidence 72. added missed dx.
  • Round 3 — confidence 78. ✓ stopped. emits final JSON.
  • Reviewer sees only the JSON. Confidence trajectory, rejected hypotheses, anchoring decisions — all gone.

TIER 1
Working memory
per-agent · invocation-local
where
state.scratchpad[agent_id]
Scratch space inside one agent invocation. The previously-unused scratchpad channel, now load-bearing — the multi-round Diagnostic loop tracks its own confidence trajectory and critique trail across LLM calls. Cleared at every invocation; never visible to other agents — that's Tier 2's role.
TIER 2
Episodic memory
current run · in-state, persisted
where
session_memory + session_summary
→ session_memory.json
The run's typed timeline plus a per-agent digest. session_memory is an append-only list of Pydantic events — critique, confidence_check, decision — that the Reviewer reads when challenging the path and the Refiner reads in full. session_summary is a one-line scoreboard per agent for cheap "is everything OK?" checks.
TIER 3
Semantic memory
cross-session · on disk
where
data/gold/memory/
semantic_memory.json
A small JSON file keyed by disease — DIRECT / INDIRECT / MISS counts, rank-1 frequency, observed evidence patterns, running average confidence. Updated by Stage 7 after every patient. Read by the Refiner and Treatment as Bayesian-style priors over the disease names appearing in the current differential.
TIER 4
Case-based memory
cross-session · vector recall
where
Qdrant collection
"patient_cases"
Each finished patient embedded with BioLORD-2023 (demographics + active conditions + medications + key labs) with the run's outcome as payload. The Diagnostic agent opens its prompt with the top-K most similar past patients — case-based recall, not static lookup. Graceful degradation if Qdrant is unreachable.
External knowledge base — not a memory tier. NICE clinical guidelines stay in the separate nice_guidelines Qdrant collection — used by the Treatment agent for drug and contraindication lookup. Reference knowledge, not memory.

07 · honest limitations

What could go wrong with the design.

  • Context inflation. Every agent now reads episodic timeline plus semantic priors plus similar past cases. Prompts grow with every patient — more tokens, more cost, and possibly less focus on the patient in front of us.
  • Anchoring bias. Case-based recall tells the Diagnostic agent "patients like this had disease X." It can pull toward X even when the current patient has a genuinely novel presentation — exactly what a diagnostic system shouldn't do.
  • Cold start. Tier 3 and Tier 4 are empty on the first patient; priors only kick in once the store warms up. The first 20–30 runs in any new disease area effectively still run memory-off.

09 · summary

Where the feature stands — and the path to scale.

4 tiers · 1 facade.

Working / Episodic / Semantic / Case-Based — accessed through one MemoryManager. New Stage-7 memory_consolidation_node. Master flag MEMORY_ENABLED.

— IMPLEMENTATION

Clean Python package.

7 modules under src/memory/. Wired into Diagnostic, Reviewer, Refiner, Treatment. 24 unit tests, all pass. Backward-compatible state shape.
